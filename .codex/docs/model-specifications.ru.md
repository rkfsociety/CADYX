# Спецификации требований к модели

CADYX проверяет небольшую версионированную JSON-спецификацию на одной сохранённой ревизии документа. Спецификация объединяет существующие инженерные проверки под именованными требованиями и возвращает их доказательства вместе. Геометрия модели не меняется.

## Agent API

Вызовите `POST /api/v1/agent/projects/{id}/validations/specification`, указав точную `expected_revision` и спецификацию версии 1. Число `12` ниже — **пример ревизии проекта**, а не версии схемы документа (которая сейчас тоже равна v12):

```json
{
  "expected_revision": 12,
  "persist": true,
  "specification": {
    "schema_version": 1,
    "title": "Требования к монтажной пластине",
    "checks": [
      {
        "id": "габаритные размеры",
        "operation": "dimensions",
        "arguments": {
          "body_id": "body-id-from-inspection",
          "expected_dimensions": {"x": 80, "y": 50, "z": 5},
          "tolerance": 0.2
        }
      },
      {
        "id": "минимальная толщина стенки",
        "operation": "thickness",
        "arguments": {
          "body_id": "body-id-from-inspection",
          "minimum_thickness": 2,
          "tolerance": 0.1,
          "method": "sampled"
        }
      }
    ]
  }
}
```

`persist` по умолчанию равен `false`. При значении `true` CADYX сохраняет одну общую запись валидации: саму спецификацию, её SHA-256, ревизию документа, результат каждой проверки и измерительные данные. Определение также можно хранить как обычный JSON-файл проекта или в системе контроля версий и передавать последующим вызовам.

Каждая проверка содержит уникальный `id`, поле `operation` и аргументы этой операции. Поддерживаются следующие операции:

- `dimensions`: сравнение габаритов тела по глобальным осям с ожидаемыми X/Y/Z в пределах допуска;
- `clearance`: проверка минимального расстояния между двумя телами с данными о возможном пересечении;
- `preservation`: сравнение эталонного и проверяемого тел по общему объёму и проверка допустимой потери объёма;
- `thickness`: проверка минимальной толщины тела существующим выборочным методом либо сертифицированным `global_minimum`.

Спецификация должна содержать от 1 до 16 проверок. Все выполняются для одной `expected_revision`. Если документ меняется во время выполнения, запрос завершается конфликтом ревизии вместо выдачи доказательств из разных состояний. Некорректное определение или аргументы приводят к ошибке запроса. Геометрически неоднозначная проверка может вернуть `untested`.

Общий статус `fail`, если не прошла хотя бы одна проверка; иначе `untested`, если осталась хотя бы одна непроверенная; в остальных случаях — `pass`. Каждая проверка содержит исходные доказательства инженерного валидатора. Инструмент MCP — `cadyx_validate_model_specification`. В процессе агента метод `validate_specification` использует последнюю наблюдавшуюся агентом ревизию.

Контракт объединяет существующие инженерные валидаторы. Он не выводит замысел детали, не создаёт проверки автоматически и не заявляет систему допусков или единиц сверх той, что предусмотрена конкретными валидаторами. Чтобы запустить согласованную необязательную строгую проверку без интерфейса, включающую эту спецификацию вместе с документом, геометрией и допустимостью экспорта, см. [проверку проекта](project-checks.md). Спецификация модели сама по себе не запускает все этапы проверки проекта.
