# CADYX project memory

- Confirmed: CADYX uses a project-local Python 3.15 runtime and a native OCCT C ABI bridge on Windows x64. Reproducible setup and reviewed stable versions: `scripts/setup-runtime.ps1`, `scripts/runtime-versions.json`; runtime artifacts stay in ignored `.runtime/`. See [setup](../README.md).
- Confirmed: `CadyxCore` is shared by the web API and Agent API. `ProjectWorkspace` writes each project's metadata, document, revision, and command history together in `projects/<directory-name>/project.json` using atomic replacement; new projects use safe display-name directories and existing workspace directories are adopted in place. UUID remains the API/lease identity; legacy UUID-named directories are readable. Canonical storage details: [project format](docs/project-format-v1.md).
- Confirmed: both project-list endpoints adopt immediate non-symlink workspace directories without a project record by atomically creating a UUID marker and empty `project.json` in place, preserving existing user files. Invalid reserved metadata is not overwritten. Browser project selection works through the Agent API, and CADYX document inspection/leases/commands require the resulting persisted project record. See [architecture](docs/architecture.md) and [project format](docs/project-format-v1.md).
- Confirmed: edit leases persist in per-project SQLite sidecars and coordinate local host processes. The same transaction protects the entire Core command and recovery; expired leases stay locked until saved state and geometry validate. Timeout is fixed at acquisition; busy operations return PROJECT_BUSY after five seconds. SSE remains process-local. See [lease contract](docs/architecture.md#edit-leases).
- Confirmed: Web API commands require a human lease; Agent API commands require an agent lease. Both invoke the same Command System.
- Confirmed: agent `/stop` persists a token fence in `.cadyx-agent.sqlite3` before waiting for the project guard, then validates saved state before releasing the agent lease. `/resume` validates an expected revision and issues a new lease whose commands require `expected_revision`. Legacy `/leases` remains compatible. Preserve both coordination sidecars while hosts run; stop older hosts before upgrading. Canonical contract: [safe agent stop/resume](docs/architecture.md#safe-agent-stop-and-resume).
- Confirmed: the in-process `AgentRuntime` uses the `AgentProvider` protocol, runs bounded inspect/viewport/command tool calls, protects every command with the current revision, refreshes the lease heartbeat, and stops through the validated agent-stop path. No provider adapter is bundled. Canonical contract: [Agent Runtime](docs/architecture.md#agent-runtime).
- Confirmed: sketch invariants and closed-profile extraction live in `cadyx/sketches.py`; constraints check supplied geometry without solving it. XY/XZ points, lines and circles render on their owning plane. Sketch points and lines support auxiliary/reference state; finite segments, infinite lines, and centerlines are represented explicitly in the scene, with reference geometry excluded from profile and sweep extraction. `add_sketch_polyline`, line chains, point/line constructors, rectangle variants, regular polygons, circle constructors, single-, double- and triple-line tangent circle constructors, exact center-defined, three-point, radius-defined, start-center-end, and line-tangent circular arcs build geometry through the shared command API. `mirror_sketch_elements` and linear/circular `pattern_sketch_elements` copy selected point/line/circle geometry with required point dependencies, without copying constraints. `extrude_sketch` and `revolve_sketch` create native OCCT B-reps linked to source sketches; point edits rebuild dependent features atomically. Sequential migrations in `cadyx/migrations.py` upgrade document v1 through v3 to current v4, while the project envelope stays v1. Canonical schema and operation contract: [Document Model v4](docs/document-model-v4.md).
- Confirmed: the browser workspace displays Core-generated body meshes and XY/XZ sketch points/lines/circles through `GET .../viewport` and `web/viewport.js`, shared with PLY previews; Z is up, and scene refresh preserves camera state. See [viewport contract](docs/viewport-api.md). Scene snapshots are cached by project revision; mesh payloads are validated as they are decoded, and PNG rendering reuses projected vertex arrays to limit peak memory. Flat-shaded viewport meshes reuse cached face normals across camera renders; geometry-changing transitions still shade their animated geometry. SSE updates local changes immediately; a five-second stat/token check recovers missed events and detects committed changes from another cooperating host, active-folder files, and changed UI assets. Changed UI assets or the browser/API compatibility version trigger an automatic page reload. The UI shows one compact current action/result or idle status; detailed activity phases remain in API snapshots and SSE data. The Agent Runtime is an in-process Python API, not embedded in the web server; external agents may continue to use the Agent API. See [architecture](docs/architecture.md).
- Confirmed: the browser is a read-only observation workspace with an agent-controlled active project, a persistent header and seven left navigation views: overview, geometry, analysis, manufacturing, activity, Files (06) and Projects (07). Projects lists saved CADYX projects and lets the user select one through the Agent API only while the current resource and target project are confirmed free; folder selection remains Agent API-only. During global agent work the UI stays locked; the progress view remains readable and shows progress/ETA, current status, the current or last actual agent action, its current or most recently finished task, and a timestamped newest-first action history. Plans and future queue entries remain in Agent API reports for the agent and do not appear in the browser. Unknown or stale availability remains locked. Files lists direct project files. CAD projects show the model viewport and front/right/top orthographic previews; Geometry exposes the object tree, Analysis shows comparison data or an empty state, and Manufacturing shows an honest empty state until toolpath data exists. Agents create projects and edit document objects through the Agent API. `GET /api/v1/agent/projects/{id}/viewport.png` returns the browser's exact main viewport frame when available, marked by `X-CADYX-Viewport-Source`; without a browser snapshot it uses the standalone isometric server renderer. Browser frames are posted with their document revision to `/api/v1/agent/projects/{id}/viewport/snapshot`. The transient `POST /api/v1/agent/projects/{id}/viewport/camera` event animates the selected browser viewer without changing the document. The local host defaults to port `8888`. Canonical contracts: [Document Model v4](docs/document-model-v4.md#browser-inspection-and-agent-api-editing), [viewport API](docs/viewport-api.md), and [run instructions](../README.md).
- Confirmed: `POST /api/v1/agent/projects/{id}/dashboard` replaces the atomically persisted agent dashboard report; both project API surfaces provide GET, `agent.dashboard` publishes report SSE updates, and `workspace.agent-work` publishes global lock changes. `/api/v1/updates` includes `dashboard_revision`, `agent_work_active`, and monotonic `agent_work_revision`. The browser disables all project controls while any workflow is below 100%, any phase/task is unfinished, or global status is unknown; it keeps the lock across reloads and host restart and clears it only at a newer fully completed revision. External Agent API integrations report workflow and queue state. Progress/ETA remain agent estimates; 100% is reported only after verified completion. Hardware telemetry is unavailable. Canonical contract: [viewport API](docs/viewport-api.md#agent-dashboard-reports).
- Confirmed user-facing visualization rule: the viewport and object tree show only the currently edited sketch when no solid feature uses it; all inactive sketches and feature source sketches are hidden. Sketch drawing and profile formation animate smoothly. The single progress card retains the current or last actual agent action and current or latest finished task, hides a duplicate task row, and lists completed/failed actions newest first with local completion times. Planned phases and future queue items stay available through the Agent API but are hidden from the browser; the full detailed journal remains available through the API. Canonical UI behavior and API details: [viewport API](docs/viewport-api.md); persistent interaction rule: [Codex rules](rules.md).
- User decision: unless a request specifies another datum, create new model geometry from global Z=0 with Z vertical. The viewport provides an exact top view and camera-oriented XYZ triad; revolved bodies identify their global Z rotation axis, which is the orbit pivot at the body's Z midpoint even when asymmetric attachments shift the scene bounds. Canonical viewport behavior: [viewport API](docs/viewport-api.md); persistent modeling rule: [Codex rules](rules.md).
- Confirmed: the Windows persistent host is registered with `scripts/manage-host-task.ps1` as an interactive at-logon Scheduled Task, loopback port `8888`, and restart-on-failure; it launches `pythonw.exe` directly, so no console appears and Task Scheduler tracks host lifetime. `scripts/run-host-background.py` captures stdout/stderr and rotates prior logs under `%LOCALAPPDATA%\CADYX`. Reinstall after moving the checkout or rebuilding the local runtime. Canonical lifecycle instructions are in [README](../README.md#keep-the-windows-host-running).
- Confirmed: `PrimitiveKernelAdapter` constructs and validates demo descriptors without B-reps; its viewport tessellation delegates to the native OCCT adapter.
- Confirmed: `OCCTKernelAdapter` is the default kernel (`OCPKernelAdapter` remains a compatibility alias). It creates and validates editable OCCT B-reps for boxes, closed-profile extrusion/revolution, C2 B-spline circular-pipe sweeps from open XY/XZ sketches, generic B-rep unions and cuts, edge fillets, and single-start external metric threads. The Agent API exposes unique current B-rep edge indices plus length, center, and curve type; indices are not persistent names. Sketch and box edits rebuild dependent sweep, fillet, fuse, and cut features atomically. Boolean cuts reject unchanged-volume and multi-solid results. The Agent Command System generates sampled unshifted involute spur-gear outlines as ordinary XY sketch geometry. Saved `primitive-v1` boxes remain compatible, and portable `cadyx-mesh-v1` triangle meshes are validated/tessellated but cannot be used as Boolean/fillet B-reps. Canonical operation limits and API contracts are in [Document Model v4](docs/document-model-v4.md).
- User decision: the browser is the user's visual observation surface; Codex operates projects/models only through Core/Agent APIs and never through virtual mouse or keyboard. Show each meaningful sketch, solid feature, camera orbit, model update, and failure through live operation events while keeping the target project visible. Implement missing modeling capabilities when the task requires them; accurately distinguish editable B-reps from triangle meshes. See [project rules](rules.md) and [viewport API](docs/viewport-api.md). Keep generated scan outputs beside source scans and preserve all originals. Project-local MCP/skill tooling is implemented: use the repo skill and `.codex/config.toml`; its stdlib adapter talks only to the Agent API. Canonical setup and safety limits: [README](../README.md#codex-operator-integration) and [architecture](docs/architecture.md#agent-api-discovery-and-local-codex-mcp-adapter).
- Confirmed: Scan-to-CAD uses the CPU Open3D C++ SDK behind a C ABI bridge, not a Python binding. `ScanProcessor` accepts direct workspace PLY sources, stores compressed mesh geometry in the document, and reprocesses only while the source SHA-256 is unchanged. The command contract, processing limits, and parameters are in [Document Model v4](docs/document-model-v4.md#scan-import-and-editable-triangle-meshes).
- Confirmed: `import_step` reads one direct project-folder STEP file through OCCT `TKDESTEP` and stores a self-contained native B-rep plus source hash and geometry metrics. Source and serialized payloads are limited to 64 MiB; the required runtime DLL closure is pinned in `scripts/occt-runtime-lock.json`. Invalid unrepairable sources remain marked invalid. Canonical contract and limits: [Document Model v4](docs/document-model-v4.md#step-import-and-editable-b-reps), [runtime setup](../scripts/setup-runtime.ps1).
- Confirmed: `export_brep` requires an exact `expected_revision` and a valid single-solid OCCT B-rep. STEP is re-imported and checked for validity, solid count, bounds and volume; optional binary STL records watertight/orientation checks, mesh volume error and a bounded sampled surface deviation. STEP/STL and the manifest are atomically published without replacing existing project files; the manifest binds the source revision and canonical geometry SHA-256. Export payloads are limited to 64 MiB. Canonical behavior and evidence limits: [verified CAD delivery](docs/document-model-v4.md#verified-cad-delivery).
- Confirmed user-provided Scan-to-CAD test data: `projects/kobras1backcover/` contains the binary PLY mesh `Merge_02_mesh.ply` and point cloud `Merge_02_pc.ply`. Preserve both source files. Both were processed successfully with the documented defaults; see [Scan-to-CAD contract](docs/document-model-v4.md#scan-import-and-editable-triangle-meshes) for current output behavior.
- Confirmed: `GET` and `POST /api/v1/agent/workspace/selection` return or select an existing project or source folder; folder/project changes publish `workspace.selection.changed` and `project.created` respectively. Selection is process-local; the browser restores its local last selection after host restart. No project/folder picker is exposed in the browser. Canonical API/UI contract: [architecture guide](docs/architecture.md#agent-controlled-workspace-selection).
