# CADYX project memory

- Confirmed: CADYX uses a project-local Python 3.15 runtime and a native OCCT C ABI bridge on Windows x64. Reproducible setup and reviewed stable versions: `scripts/setup-runtime.ps1`, `scripts/runtime-versions.json`; runtime artifacts stay in ignored `.runtime/`. See [setup](../README.md).
- Confirmed: `CadyxCore` is shared by the web API and Agent API. `ProjectWorkspace` writes each project's metadata, document, revision, and command history together in `projects/<safe-display-name>/project.json` using atomic replacement. UUID remains the API/lease identity; legacy UUID-named directories are readable. Canonical storage details: [project format](docs/project-format-v1.md).
- Confirmed: `GET /api/v1/projects` and `GET /api/v1/agent/projects` list immediate directories without a CADYX `project.json` in `folders`. The web UI treats them as selectable projects; CADYX document inspection/leases/commands still require a persisted project record. See [architecture](docs/architecture.md).
- Confirmed: folder projects expose direct regular files through the workspace file API. The browser previews binary little-endian PLY meshes and point clouds with a downsampled canvas renderer that fills the desktop workspace; drag orbits the camera, the wheel zooms, and a double-click resets the view. Source files are read-only. PLY parsing skips unused list payloads with byte-length checks; scan buffer conversion avoids intermediate byte copies, and generated-file reuse hashes incrementally. See [architecture](docs/architecture.md) and `web/ply-preview.js`.
- Confirmed: edit leases persist in per-project SQLite sidecars and coordinate local host processes. The same transaction protects the entire Core command and recovery; expired leases stay locked until saved state and geometry validate. Timeout is fixed at acquisition; busy operations return PROJECT_BUSY after five seconds. SSE remains process-local. See [lease contract](docs/architecture.md#edit-leases).
- Confirmed: Web API commands require a human lease; Agent API commands require an agent lease. Both invoke the same Command System.
- Confirmed: agent `/stop` persists a token fence in `.cadyx-agent.sqlite3` before waiting for the project guard, then validates saved state before releasing the agent lease. `/resume` validates an expected revision and issues a new lease whose commands require `expected_revision`. Legacy `/leases` remains compatible. Preserve both coordination sidecars while hosts run; stop older hosts before upgrading. Canonical contract: [safe agent stop/resume](docs/architecture.md#safe-agent-stop-and-resume).
- Confirmed: the in-process `AgentRuntime` uses the `AgentProvider` protocol, runs bounded inspect/viewport/command tool calls, protects every command with the current revision, refreshes the lease heartbeat, and stops through the validated agent-stop path. No provider adapter is bundled. Canonical contract: [Agent Runtime](docs/architecture.md#agent-runtime).
- Confirmed: sketch invariants and closed-profile extraction live in `cadyx/sketches.py`; constraints check supplied geometry without solving it. XY/XZ points, lines and circles render on their owning plane. `add_sketch_polyline` and `add_sketch_rectangle` atomically build point/line objects; `add_sketch_circle` creates its center and circle together through the shared command API. `extrude_sketch` and `revolve_sketch` create native OCCT B-reps linked to source sketches; point edits rebuild dependent features atomically. Sequential migrations in `cadyx/migrations.py` upgrade document v1 through v2 to current v3, while the project envelope stays v1. Canonical schema and operation contract: [Document Model v3](docs/document-model-v3.md).
- Confirmed: the browser workspace displays Core-generated body meshes and XY/XZ sketch points/lines/circles through `GET .../viewport` and `web/viewport.js`, shared with PLY previews; Z is up, and scene refresh preserves camera state. See [viewport contract](docs/viewport-api.md). Scene snapshots are cached by project revision; mesh payloads are validated as they are decoded, and PNG rendering reuses projected vertex arrays to limit peak memory. SSE updates local changes immediately; a five-second stat/token check recovers missed events and detects committed changes from another cooperating host, active-folder files, and changed UI assets. Changed UI assets trigger an automatic page reload. The UI shows one compact current action/result or idle status; detailed activity phases remain in API snapshots and SSE data. The Agent Runtime is an in-process Python API, not embedded in the web server; external agents may continue to use the Agent API. See [architecture](docs/architecture.md).
- Confirmed: the browser is a read-only detail workspace centered on a dominant model viewport, with left section navigation and a right column for live agent status, agent-reported workflow estimates/task queue, and front/right/top orthographic previews. Model and property docks start collapsed. Agents create projects and edit document objects through the Agent API, and can fetch an isometric PNG scene image from `GET /api/v1/agent/projects/{id}/viewport.png` without a browser. The transient `POST /api/v1/agent/projects/{id}/viewport/camera` event animates the selected browser viewer without changing the document. The local host defaults to port `8888`. Canonical contracts: [Document Model v3](docs/document-model-v3.md#browser-inspection-and-agent-api-editing), [viewport API](docs/viewport-api.md), and [run instructions](../README.md).
- Confirmed: `POST /api/v1/agent/projects/{id}/dashboard` replaces the process-local agent dashboard report; both project API surfaces provide GET, `agent.dashboard` publishes SSE updates, and `/api/v1/updates` includes `dashboard_revision`. External Agent API integrations report workflow and queue state. Progress/ETA are agent estimates, and hardware telemetry is unavailable. Canonical contract: [viewport API](docs/viewport-api.md#agent-dashboard-reports).
- Confirmed user-facing visualization rule: the viewport and object tree show only the currently edited sketch when no solid feature uses it; all inactive sketches and feature source sketches are hidden. Sketch drawing and profile formation animate smoothly. The agent card shows current action/result/idle, with detailed journal data available through the API; workflow phases and queue rows come from the explicit dashboard report. Canonical UI behavior and API details: [viewport API](docs/viewport-api.md); persistent interaction rule: [Codex rules](rules.md).
- User decision: unless a request specifies another datum, create new model geometry from global Z=0 with Z vertical. The viewport provides an exact top view and camera-oriented XYZ triad; revolved bodies identify their global Z rotation axis, which is the orbit pivot at the body's Z midpoint even when asymmetric attachments shift the scene bounds. Canonical viewport behavior: [viewport API](docs/viewport-api.md); persistent modeling rule: [Codex rules](rules.md).
- Confirmed: the Windows persistent host is registered with `scripts/manage-host-task.ps1` as an interactive at-logon Scheduled Task, loopback port `8888`, and restart-on-failure; it launches `pythonw.exe` directly, so no console appears and Task Scheduler tracks host lifetime. `scripts/run-host-background.py` captures stdout/stderr and rotates prior logs under `%LOCALAPPDATA%\CADYX`. Reinstall after moving the checkout or rebuilding the local runtime. Canonical lifecycle instructions are in [README](../README.md#keep-the-windows-host-running).
- Confirmed: `PrimitiveKernelAdapter` constructs and validates demo descriptors without B-reps; its viewport tessellation delegates to the native OCCT adapter.
- Confirmed: `OCCTKernelAdapter` is the default kernel (`OCPKernelAdapter` remains a compatibility alias). It creates and validates editable OCCT B-reps for boxes, closed-profile extrusion/revolution, C2 B-spline circular-pipe sweeps from open XY/XZ sketches, generic B-rep unions, edge fillets, and single-start external metric threads. The Agent API exposes unique current B-rep edge indices plus length, center, and curve type; indices are not persistent names. Sketch edits rebuild dependent sweep, fillet, and fuse features atomically. The Agent Command System generates sampled unshifted involute spur-gear outlines as ordinary XY sketch geometry. Saved `primitive-v1` boxes remain compatible, and portable `cadyx-mesh-v1` triangle meshes are validated/tessellated but cannot be used as Boolean/fillet B-reps. Canonical operation limits and API contracts are in [Document Model v3](docs/document-model-v3.md).
- User decision: the browser is the user's visual observation surface; Codex operates projects/models only through Core/Agent APIs and never through virtual mouse or keyboard. Show each meaningful sketch, solid feature, camera orbit, model update, and failure through live operation events while keeping the target project visible. Implement missing modeling capabilities when the task requires them; accurately distinguish editable B-reps from triangle meshes. See [project rules](rules.md) and [viewport API](docs/viewport-api.md). Keep generated scan outputs beside source scans and preserve all originals. Project-local MCP/skill/plugin tooling is authorized for concrete future needs, but is deferred until a task requires it.
- Confirmed: Scan-to-CAD uses the CPU Open3D C++ SDK behind a C ABI bridge, not a Python binding. `ScanProcessor` accepts direct workspace PLY sources, stores compressed mesh geometry in the document, and reprocesses only while the source SHA-256 is unchanged. The command contract, processing limits, and parameters are in [Document Model v3](docs/document-model-v3.md#scan-import-and-editable-triangle-meshes).
- Confirmed: `import_step` reads one direct project-folder STEP file through OCCT `TKDESTEP` and stores a self-contained native B-rep plus source hash and geometry metrics. Source and serialized payloads are limited to 64 MiB; the required runtime DLL closure is pinned in `scripts/occt-runtime-lock.json`. Invalid unrepairable sources remain marked invalid. Canonical contract and limits: [Document Model v3](docs/document-model-v3.md#step-import-and-editable-b-reps), [runtime setup](../scripts/setup-runtime.ps1).
- Confirmed: `export_brep` requires an exact `expected_revision` and a valid single-solid OCCT B-rep. STEP is re-imported and checked for validity, solid count, bounds and volume; optional binary STL records watertight/orientation checks, mesh volume error and a bounded sampled surface deviation. STEP/STL and the manifest are atomically published without replacing existing project files; the manifest binds the source revision and canonical geometry SHA-256. Export payloads are limited to 64 MiB. Canonical behavior and evidence limits: [verified CAD delivery](docs/document-model-v3.md#verified-cad-delivery).
- Confirmed user-provided Scan-to-CAD test data: `projects/kobras1backcover/` contains the binary PLY mesh `Merge_02_mesh.ply` and point cloud `Merge_02_pc.ply`. Preserve both source files. Both were processed successfully with the documented defaults; see [Scan-to-CAD contract](docs/document-model-v3.md#scan-import-and-editable-triangle-meshes) for current output behavior.
