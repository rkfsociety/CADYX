# CADYX project memory

- User direction: reference-driven model creation and study should also improve CADYX. Look for concrete workflow or capability gaps while modeling; implement and verify relevant improvements, document reusable confirmed behavior in canonical docs, and keep source-specific measurements and transcripts in the individual CADYX project rather than shared memory. Persistent instruction: [rules](rules.md).

- Confirmed: CADYX uses a project-local Python 3.15 runtime and a native OCCT C ABI bridge on Windows x64. Reproducible setup and reviewed stable versions: `scripts/setup-runtime.ps1`, `scripts/runtime-versions.json`; runtime artifacts stay in ignored `.runtime/`. See [setup](../README.md).
- Confirmed: `CadyxCore` is shared by the web API and Agent API. `ProjectWorkspace` writes each project's metadata, document, revision, and command history together in `projects/<directory-name>/project.json` using atomic replacement; new projects use safe display-name directories and existing workspace directories are adopted in place. UUID remains the API/lease identity; legacy UUID-named directories are readable. Canonical storage details: [project format](docs/project-format-v1.md).
- Confirmed: both project-list endpoints adopt immediate non-symlink workspace directories without a project record by atomically creating a UUID marker and empty `project.json` in place, preserving existing user files. Invalid reserved metadata is not overwritten. Browser project selection works through the Agent API, and CADYX document inspection/leases/commands require the resulting persisted project record. See [architecture](docs/architecture.md) and [project format](docs/project-format-v1.md).
- Confirmed: Projects view groups are logical labels persisted in workspace-root `.cadyx-project-groups.sqlite3`; assigning a project requires it to be free with no running operation and does not move its directory. Canonical API and UI behavior: [architecture](docs/architecture.md#agent-controlled-workspace-selection).
- Confirmed: deleting a project uses authenticated `DELETE /api/v1/projects/{id}`, requires a free project with no running operation, and removes its project directory after the browser confirmation. The delete marker fences new lease requests while the directory is detached; see [architecture](docs/architecture.md#agent-controlled-workspace-selection).
- Confirmed: edit leases persist in per-project SQLite sidecars and coordinate local host processes. The same transaction protects the entire Core command and recovery; expired leases stay locked until saved state and geometry validate. Timeout is fixed at acquisition; busy operations return PROJECT_BUSY after five seconds. SSE remains process-local. See [lease contract](docs/architecture.md#edit-leases).
- Confirmed: the atomic `clear_model` command removes all saved model objects while preserving document identity, project history, and staged files. It is intended only for an explicit clean-model request; see [Document Model v7](docs/document-model-v7.md#model-commands).
- Confirmed: Web API commands require a human lease; Agent API commands require an agent lease. Both invoke the same Command System.
- Confirmed: agent `/stop` persists a token fence in `.cadyx-agent.sqlite3` before waiting for the project guard, then validates saved state before releasing the agent lease. `/resume` validates an expected revision and issues a new lease whose commands require `expected_revision`. Legacy `/leases` remains compatible. Preserve both coordination sidecars while hosts run; stop older hosts before upgrading. Canonical contract: [safe agent stop/resume](docs/architecture.md#safe-agent-stop-and-resume).
- Confirmed: the in-process `AgentRuntime` uses the `AgentProvider` protocol, runs bounded inspect/viewport/command tool calls, protects every command with the current revision, refreshes the lease heartbeat, and stops through the validated agent-stop path. No provider adapter is bundled. Canonical contract: [Agent Runtime](docs/architecture.md#agent-runtime).
- Confirmed: sketch invariants and closed-profile extraction live in `cadyx/sketches.py`; constraints check supplied geometry without solving it. XY/XZ points, lines, circles, exact analytic ellipses and elliptical arcs, and sketch splines render on their owning plane. Sketch points and lines support auxiliary/reference state; finite segments, infinite lines, and centerlines are represented explicitly in the scene, with reference geometry excluded from profile and sweep extraction. `add_sketch_polyline`, line chains, point/line constructors, rectangle variants, regular polygons, circle constructors, single-, double- and triple-line tangent circle constructors, exact center-defined, three-point, radius-defined, start-center-end, line-tangent circular arcs, and ellipses defined from major-axis endpoints, center/radii, or perpendicular three-point axes, elliptical arcs, an open centripetal Catmull-Rom spline through 3–128 points, and an open clamped uniform control-point B-spline through 3–128 controls build geometry through the shared command API. `mirror_sketch_elements` and linear/circular `pattern_sketch_elements` copy selected point/line/circle/ellipse/spline geometry and required point dependencies, without copying constraints. `extrude_sketch` and `revolve_sketch` create native OCCT B-reps linked to source sketches; point edits rebuild dependent features atomically. Sequential migrations in `cadyx/migrations.py` upgrade document v1 through v6 to current v7, while the project envelope stays v1. Canonical schema and operation contract: [Document Model v7](docs/document-model-v7.md).
- Confirmed: `revolve_sketch` stores overall `outer_diameter` and `height` parameters. `set_parameter` scales the linked closed XZ profile radially or from its lower axial datum and rebuilds the native B-rep; Geometry exposes these two values as editable dimensions. Verified both dimensions by changing and restoring them on a saved project. Canonical contract: [Document Model v7](docs/document-model-v7.md#sketch-driven-solid-features).
- Confirmed: body patterns, holes and bosses retain their source-body dependency and rebuild after upstream geometry edits. `set_parameter` edits circular-pattern count/step and hole/boss diameter/depth; a full-circle pattern keeps `angle_step_degrees = 360/count` when its count changes. Pattern seed bodies are hidden as intermediate history in the scene. Canonical contract: [Document Model v7](docs/document-model-v7.md#sketch-driven-solid-features).
- Confirmed: the browser workspace displays Core-generated body meshes and XY/XZ sketch points/lines/circles/ellipses through `GET .../viewport` and `web/viewport.js`, shared with PLY previews; Z is up, and scene refresh preserves camera state. See [viewport contract](docs/viewport-api.md). Scene snapshots are cached by project revision; mesh payloads are validated as they are decoded, and PNG rendering reuses projected vertex arrays to limit peak memory. Flat-shaded viewport meshes reuse cached face normals across camera renders; geometry-changing transitions still shade their animated geometry. SSE updates local changes immediately; a five-second stat/token check recovers missed events and detects committed changes from another cooperating host, active-folder files, and changed UI assets. Changed UI assets or the browser/API compatibility version trigger an automatic page reload. The UI shows one compact current action/result or idle status; detailed activity phases remain in API snapshots and SSE data. The Agent Runtime is an in-process Python API, not embedded in the web server; external agents may continue to use the Agent API. See [architecture](docs/architecture.md).
- Confirmed: the browser is a read-only observation workspace with an agent-controlled active project, a compact persistent header and seven compact left-rail navigation views: overview, geometry, analysis, manufacturing, activity, Files (06) and Projects (07). The Overview is viewport-first: the main CAD canvas occupies the workspace, model/revision metrics are presented as an in-viewport HUD, agent ownership is surfaced in the header, and the progress block is a compact overlay that can expand to its action history when controls are available. Front/right/top orthographic previews are hidden from the default layout and appear on demand through the `4 ВИДА` viewport control, producing a four-pane inspection layout with the main model plus three orthographic views. Projects lists saved CADYX projects and lets the user select one through the Agent API only while the current resource and target project are confirmed free; folder selection remains Agent API-only. Controls lock for a project while that project has active agent work; a different project remains usable only when its API lock and activity snapshot confirm it free. Projects (07) remains available during agent work so the user can navigate to the project chooser. Global status unknown and stale project availability remain locked; new viewport/layout controls follow the same fail-closed lock. The progress view remains readable and shows progress/ETA, current status, the current or last actual agent action, its current or most recently finished task, and a timestamped newest-first action history. Plans and future queue entries remain in Agent API reports for the agent and do not appear in the browser. Files lists direct project files. Geometry exposes the object tree, Analysis shows comparison data or an empty state, and Manufacturing shows an honest empty state until toolpath data exists. Agents create projects and edit document objects through the Agent API. `GET /api/v1/agent/projects/{id}/viewport.png` returns the browser's exact main viewport frame when available, marked by `X-CADYX-Viewport-Source`; without a browser snapshot it uses the standalone isometric server renderer. Browser frames are posted with their document revision to `/api/v1/agent/projects/{id}/viewport/snapshot`. The transient `POST /api/v1/agent/projects/{id}/viewport/camera` event animates the selected browser viewer without changing the document. The local host defaults to port `8888`. Canonical contracts: [Document Model v7](docs/document-model-v7.md#browser-inspection-and-agent-api-editing), [viewport API](docs/viewport-api.md), and [run instructions](../README.md).
- Confirmed: `POST /api/v1/agent/projects/{id}/dashboard` replaces the atomically persisted agent dashboard report; both project API surfaces provide GET, `agent.dashboard` publishes report SSE updates, and `workspace.agent-work` publishes global lock changes. `/api/v1/updates` includes `dashboard_revision`, `agent_work_active`, active workflow project IDs, and monotonic `agent_work_revision`. The browser uses `agent_work_active_project_ids` to match active workflow locks to project UUIDs and keeps the per-project lock across reloads and host restart; a project remains locked while its workflow is unfinished or its own availability is unknown/stale. Global status unknown remains fail-closed. The Agent API may select the sole project with active work to restore its viewer after a host restart; switching to another resource remains blocked until work completes. Progress/ETA remain agent estimates; 100% is reported only after verified completion. Hardware telemetry is unavailable. Canonical contract: [viewport API](docs/viewport-api.md#agent-dashboard-reports) and [workspace selection](docs/architecture.md#agent-controlled-workspace-selection).
- Confirmed user-facing visualization rule: the viewport and object tree show only the currently edited sketch when no solid feature uses it; all inactive sketches and feature source sketches are hidden. Sketch drawing and profile formation animate smoothly. The single progress card is a compact Overview overlay by default, retains the current or last actual agent action and current or latest finished task, hides a duplicate task row, and can expand to the completed/failed newest-first action history when browser controls are unlocked. During agent ownership, the header and viewport show the locked/AI-editing state while all new user-operated layout controls remain disabled under the same fail-closed rule as existing controls. Planned phases and future queue items stay available through the Agent API but are hidden from the browser; the full detailed journal remains available through the API. Canonical UI behavior and API details: [viewport API](docs/viewport-api.md); persistent interaction rule: [Codex rules](rules.md).
- User decision: unless a request specifies another datum, create new model geometry from global Z=0 with Z vertical. The viewport provides an exact top view and camera-oriented XYZ triad; revolved bodies identify their global Z rotation axis, which is the orbit pivot at the body's Z midpoint even when asymmetric attachments shift the scene bounds. Canonical viewport behavior: [viewport API](docs/viewport-api.md); persistent modeling rule: [Codex rules](rules.md).
- Confirmed: the Windows persistent host is registered with `scripts/manage-host-task.ps1` as an interactive at-logon Scheduled Task, loopback port `8888`, and restart-on-failure; it launches `pythonw.exe` directly, so no console appears and Task Scheduler tracks host lifetime. `scripts/run-host-background.py` captures stdout/stderr and rotates prior logs under `%LOCALAPPDATA%\CADYX`. Reinstall after moving the checkout or rebuilding the local runtime. Canonical lifecycle instructions are in [README](../README.md#keep-the-windows-host-running).
- Confirmed: `PrimitiveKernelAdapter` constructs and validates demo descriptors without B-reps; its viewport tessellation delegates to the native OCCT adapter.
- Confirmed: `OCCTKernelAdapter` is the default kernel (`OCPKernelAdapter` remains a compatibility alias). It creates and validates editable OCCT B-reps for boxes, closed-profile extrusion/revolution, C2 B-spline circular-pipe sweeps from open XY/XZ sketches, sampled STEP-section sketches, capped lofts through ordered XZ sections, generic B-rep unions and cuts, edge fillets, and single-start external metric threads. Section and loft sketches retain their station metadata; edits rebuild dependent loft, sweep, fillet, fuse, and cut features atomically. Loft descriptors can be fused through the operation graph. Section curves and lofts are sampled polygon approximations, not exact recovery of STEP analytic or NURBS surfaces. The Agent API exposes unique current B-rep edge indices plus length, center, and curve type; indices are not persistent names. Sketch and box edits rebuild dependent features atomically. Boolean cuts reject unchanged-volume and multi-solid results. The Agent Command System generates sampled unshifted involute spur-gear outlines as ordinary XY sketch geometry. Saved `primitive-v1` boxes remain compatible, and portable `cadyx-mesh-v1` triangle meshes are validated/tessellated but cannot be used as Boolean/fillet B-reps. Canonical operation limits and API contracts are in [Document Model v7](docs/document-model-v7.md).
- Confirmed: loft section start-vertex correspondence is persisted as `profile_alignment` so validation and dependent-feature rebuilds use the same cyclic alignment rule. Old v7 loft descriptors without the marker retain independent-start behavior; current simple lofts use `minimum-displacement-v2`. Grouped sections approximate contour split/merge through adjacent two-section branches; polynomial assignment pairs contours by centroid proximity and enclosed area, and the final B-rep must be one connected solid. Model sketch and feature counts have no fixed ceiling. This does not track persistent surface identity, so validate the fit against its source. See [loft contract](docs/document-model-v7.md).

- Confirmed: Scan-to-CAD uses the CPU Open3D C++ SDK behind a C ABI bridge, not a Python binding. `ScanProcessor` accepts direct workspace PLY sources, stores compressed mesh geometry in the document, and reprocesses only while the source SHA-256 is unchanged. The command contract, processing limits, and parameters are in [Document Model v7](docs/document-model-v7.md#scan-import-and-editable-triangle-meshes).
- Confirmed: scan reverse engineering now bridges the reconstructed `cadyx-mesh-v1` reference into editable CAD authoring. `align_scan` provides deterministic PCA or explicit right-handed datum alignment, explicit scale/units and optional Z grounding; stored alignment is reapplied after `set_scan_parameter`. `create_sketch_from_scan_section` and batched `create_scan_sections` extract closed Y/Z-normal mesh contours into ordinary editable sketches; Y-normal XZ station groups feed the existing `loft_sketches` command directly. `compare_body_to_scan` reports sampled BVH point-to-triangle mean/RMS/P95/max deviation (optionally bidirectional and tolerance-scored) against the B-rep viewport tessellation. Units are never inferred from PLY data and the comparison is sampled rather than exact metrology. Canonical contract: [scan reverse engineering](docs/scan-reverse-engineering.md).
- Confirmed: the authenticated Agent API stages direct `.step`/`.stp` files up to 64 MiB through an atomic, no-overwrite binary upload route; `remove_body` accepts `remove_source_file: true` to remove an imported reference body and its staged STEP after saving, while the standalone `cadyx_remove_staged_step` route refuses a STEP still used by an `import_step` feature. The local MCP uploader transfers bytes from a local regular file; cleanup does not touch that original. Canonical contract: [architecture](docs/architecture.md#core-and-storage), [Document Model v7](docs/document-model-v7.md#step-import-and-editable-b-reps).
- Confirmed: `import_step` reads one direct project-folder STEP file through OCCT `TKDESTEP` and stores a self-contained native B-rep plus source hash and geometry metrics. Source and serialized payloads are limited to 64 MiB; the required runtime DLL closure is pinned in `scripts/occt-runtime-lock.json`. Invalid unrepairable sources remain marked invalid. `show_in_preview: false` keeps an imported reference available to commands while excluding it from viewport scenes and project thumbnails; legacy bodies with no visibility flag remain visible. Canonical contract and limits: [Document Model v7](docs/document-model-v7.md#step-import-and-editable-breps), [runtime setup](../scripts/setup-runtime.ps1).

STEP/STL and the manifest are atomically published without replacing existing project files; the manifest binds the source revision and canonical geometry SHA-256. Export payloads are limited to 64 MiB. Canonical behavior and evidence limits: [verified CAD delivery](docs/document-model-v7.md#verified-cad-delivery).
