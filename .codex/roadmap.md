# CADYX project roadmap

This is the current development sequence. The milestones are goals, not claims that the corresponding capabilities are entirely absent; inspect the implementation before starting work or changing a milestone's status. Stages 1–13 are complete.

## Stages

1. **Complete — Real geometry kernel:** integrate Open CASCADE behind `GeometryKernel`, validate reconstructed box B-reps, retain compatibility with saved `primitive-v1` descriptors, and cover the adapter with conformance tests. Evidence: [`cadyx/kernel.py`](../cadyx/kernel.py), [`tests/test_kernel.py`](../tests/test_kernel.py), and [runtime setup](../scripts/setup-runtime.ps1).
2. **Complete — Live visual workspace:** show supported CAD bodies, sketch geometry and parameter changes in the browser as APIs update the project; animate meaningful sketch edits and extrusion, revolution, sweep, Boolean fuse and fillet operations. Activity snapshots and SSE carry detailed operation status and progress, while the browser shows one compact action/result status; the selected project stays visible during agent work. Evidence: [`web/`](../web/), [`cadyx/web.py`](../cadyx/web.py), and [architecture](docs/architecture.md).
3. **Complete — Editable Document Model and feature history:** persisted XY/XZ sketches with points, lines, circles, exact analytic ellipses and elliptical arcs, open point-interpolating Catmull–Rom splines, open clamped control-point B-splines, and periodic OCCT B-splines for new closed-spline profiles. Legacy `closed_catmull_rom` geometry descriptors remain readable and rebuild through their original cubic B-spline edge chains. Checked horizontal/vertical/coincident/distance/radius constraints, stable typed UUID references, atomic batch edits and guarded deletion. Closed profiles create editable OCCT extrusion/revolution features; open sketch paths create B-spline circular-pipe sweeps; source bodies can be fused into one solid and topology-selected edges filleted. Replacing or editing sketch profiles/paths and changing supported feature parameters rebuilds dependent features atomically. Constraints validate supplied geometry; no solver or browser sketch editor is included. Document v1–v6 upgrade explicitly to v7 in memory, preserving legacy solids/history. Evidence: [`cadyx/models.py`](../cadyx/models.py), [`cadyx/sketches.py`](../cadyx/sketches.py), [`cadyx/commands.py`](../cadyx/commands.py), [`native/kernel.cpp`](../native/kernel.cpp), and [document contract](docs/document-model-v7.md).
4. **Complete — Project Format migrations:** explicit sequential migrations with independent project-envelope/document versions, copy-only reads, current-schema validation and persistence through successful leased commands and the existing atomic save path. Envelope v1 and document v7 are current. Evidence: [`cadyx/migrations.py`](../cadyx/migrations.py), [`tests/test_migrations.py`](../tests/test_migrations.py), [`tests/test_web_api.py`](../tests/test_web_api.py), and [migration contract](docs/project-format-v1.md#migration-contract).
5. **Complete — Multi-process leases:** durable per-project SQLite leases and a shared lock spanning the full Core command, inspection and validated stale-lease recovery on local filesystems; process crashes retain recoverable lease ownership and atomic project state. Independent projects remain concurrent. SSE stays process-local. Evidence: [`cadyx/lease.py`](../cadyx/lease.py), [`cadyx/core.py`](../cadyx/core.py), [`tests/test_multiprocess_leases.py`](../tests/test_multiprocess_leases.py), and [lease contract](docs/architecture.md#edit-leases).
6. **Complete — Safe agent stop and resume:** durable per-token stop fences reject queued commands while an admitted atomic command finishes; saved document and geometry validate before the agent lease is freed. Resume validates the expected revision and issues a fresh lease whose commands require revision checks. Saved history resolves uncertain command outcomes without automatic replay. Existing lease acquisition remains compatible; no embedded runtime or UI stop controls are included. Evidence: [`cadyx/core.py`](../cadyx/core.py), [`cadyx/lease.py`](../cadyx/lease.py), [`cadyx/web.py`](../cadyx/web.py), [`tests/test_agent_control.py`](../tests/test_agent_control.py), [`tests/test_multiprocess_leases.py`](../tests/test_multiprocess_leases.py), [`tests/test_web_api.py`](../tests/test_web_api.py), and [stop/resume contract](docs/architecture.md#safe-agent-stop-and-resume).
7. **Complete — Shared rendering and viewport API:** identical read-only scene endpoints for browser/agents, native OCCT tessellation of boxes, extrusion/revolution profiles, swept pipes, fused solids and filleted solids, plus direct rendering of editable scan triangle meshes and XY/XZ sketch points, lines, circles, ellipses and splines. Scenes expose stable object ids and bounds/revision. A shared Z-up orthographic canvas viewport renders CAD scenes and PLY with orbit, zoom, fit and client camera API; Agent API camera events animate a visible browser orbit without synthesizing input, and document refresh retains the camera. The semantic browser overlay supports body picking and feature selection by projected tessellation triangles. It projects each mesh vertex once per click, checks all triangles with a screen-space bounding-box rejection before point-in-triangle testing, interpolates depth at the pointer, and selects the nearest visible body feature. Scan meshes remain distinct from B-reps and are not Boolean/fillet inputs. The latest stable Python/OCCT runtime uses a native C ABI bridge. No browser sketch editor is included. Evidence: [`cadyx/rendering.py`](../cadyx/rendering.py), [`native/`](../native/), [`web/viewport.js`](../web/viewport.js), [`web/app.js`](../web/app.js), [`tests/test_rendering.py`](../tests/test_rendering.py), [`tests/test_profile_features.py`](../tests/test_profile_features.py), [`tests/test_viewport.cjs`](../tests/test_viewport.cjs), [`tests/test_web_api.py`](../tests/test_web_api.py), and [viewport contract](docs/viewport-api.md).
8. **Complete — CAD model inspection and API-first authoring:** use a read-only, full-window detail view with collapsed model and property docks. Agents create projects and author/edit bodies, sketches, geometry, constraints and dependent solid features through the existing Agent API and Core command system; they can inspect current B-rep edge topology for fillets and retrieve the exact browser viewport PNG through `viewport.png` when available, with a standalone server-render fallback. SSE updates the observation view after committed changes and animates API-requested camera orbits and modeling operations, without a manual page refresh. The browser provides observation only. Evidence: [`web/index.html`](../web/index.html), [`web/app.js`](../web/app.js), [`web/style.css`](../web/style.css), [`cadyx/rendering.py`](../cadyx/rendering.py), [`tests/test_web_api.py`](../tests/test_web_api.py), [`tests/test_profile_features.py`](../tests/test_profile_features.py), [Agent API contract](docs/document-model-v7.md#browser-inspection-and-agent-api-editing), and [viewport contract](docs/viewport-api.md).
9. **Complete — Provider-neutral Agent Runtime:** add an in-process runtime with a provider adapter protocol, bounded tool loop, project inspection and viewport tools, and revision-protected Command System execution under managed agent leases. Core remains provider-independent and no provider SDK or adapter is bundled. Evidence: [`cadyx/agent_runtime.py`](../cadyx/agent_runtime.py), [`tests/test_agent_runtime.py`](../tests/test_agent_runtime.py), and [runtime contract](docs/architecture.md#agent-runtime).
10. **Complete — Authentication before LAN access:** reject unauthenticated non-loopback binds; protect the browser, API, workspace files, viewport and SSE with a configured token; keep only minimal health status public. Tokens come from one validated runtime source, and the default persistent host remains loopback-only. Evidence: [`cadyx/auth.py`](../cadyx/auth.py), [`cadyx/__main__.py`](../cadyx/__main__.py), [`cadyx/web.py`](../cadyx/web.py), [`tests/test_auth.py`](../tests/test_auth.py), and [authentication contract](docs/architecture.md#http-authentication-and-lan-bind-gate).
11. **Complete — Scan-to-CAD:** import direct workspace PLY triangle meshes and point clouds, clean/simplify meshes or reconstruct point-cloud surfaces with CPU Open3D, and persist editable `cadyx-mesh-v1` geometry plus bounded parameters/source hash in the document. Export each processed mesh as an atomic content-addressed PLY beside its unchanged source. Publish actual operation phases and recent activity in Core snapshots and Agent API/SSE data; show one compact action/result status in the browser. Evidence: [`cadyx/scan.py`](../cadyx/scan.py), [`native/scan.cpp`](../native/scan.cpp), [`cadyx/mesh_geometry.py`](../cadyx/mesh_geometry.py), [`cadyx/commands.py`](../cadyx/commands.py), [`web/`](../web/), [`tests/test_scan.py`](../tests/test_scan.py), [`tests/test_web_api.py`](../tests/test_web_api.py), [scan command contract](docs/document-model-v7.md#scan-import-and-editable-triangle-meshes), and [runtime setup](../scripts/setup-runtime.ps1). Checks: native runtime setup/build, real mesh and point-cloud sample processing in an isolated temporary workspace, scan/API/Agent Runtime and kernel/document/rendering test modules.
12. **Complete — Engineering gears and threads:** build unshifted external involute spur-gear outlines through the existing XY sketch command, and single-start external ISO metric thread solids as editable native OCCT features. Preserve Document Model v6 and agent-only modeling; animate profile strokes and thread creation in the live viewer. Evidence: [`cadyx/engineering.py`](../cadyx/engineering.py), [`cadyx/commands.py`](../cadyx/commands.py), [`native/kernel.cpp`](../native/kernel.cpp), [engineering profile contract](docs/document-model-v7.md#engineering-profiles), [`tests/test_engineering_features.py`](../tests/test_engineering_features.py), and [viewport contract](docs/viewport-api.md). Checks: native OCCT rebuild, targeted engineering feature tests, and live Agent API demo projects for a 20/40-tooth module-2 gear pair and a parameter-edited M12x1.5 thread.
13. **Complete — Verified CAD delivery:** export a validated single-solid B-rep as exact STEP and optional STL through the existing Core/Command System and native kernel boundary. Publish revision-bound, content-addressed files plus a manifest atomically without replacing user files. The manifest records source geometry identity, kernel version, file hashes/sizes, round-trip STEP validity/solid count/bounds/volume, and STL watertightness/orientation/relative-volume checks with a bounded sampled surface-deviation method. STEP remains authoritative; sampling and physical fit/strength/printing claims are kept distinct. Evidence: [`cadyx/commands.py`](../cadyx/commands.py), [`cadyx/delivery.py`](../cadyx/delivery.py), [`cadyx/workspace.py`](../cadyx/workspace.py), [`native/kernel.cpp`](../native/kernel.cpp), [`tests/test_delivery.py`](../tests/test_delivery.py), [document contract](docs/document-model-v7.md#verified-cad-delivery), and [architecture](docs/architecture.md). Checks: native OCCT build; delivery (3), kernel (11), and Web API (15) targeted tests; `compileall`; `git diff --check`; and a 6,249,449-byte complex STEP sample imported in 2.249 s to a 3,608,531-byte serialized B-rep (1 solid, 249 faces, 809 edges, 535 vertices). STEP re-import passed with identical bounds and 5.81e-11 relative volume error. STL passed watertight/orientation checks with 16,992 triangles, 0.000986 relative volume error, and a 64-centroid sample measuring 0.04444 maximum / 0.02001 RMS deviation in model units. The viewport retained one object and a 42,646-byte PNG before and after export.

## Candidate next milestones

These are proposed follow-on goals, not implemented capabilities or committed schedules. Inspect current code before starting each one.

14. **In progress — Revision-bound engineering validation:** implemented read-only axis-aligned body-dimension, OCCT B-rep minimum-distance/common-volume, reference/candidate preserved-volume, and sampled inward-normal wall-thickness checks through the Agent API/MCP. Responses bind to the saved revision and geometry hash and report model units, method, tolerances, witnesses or volume deltas, and `pass`/`fail`/`untested` status. Clearance and wall-thickness checks publish OCCT progress through agent activity events. Optional immutable validation records are stored in a project-local SQLite sidecar and can be listed through the Agent API/MCP without changing the document revision. Thickness sampling can flag an observed thin-wall chord but cannot certify the global minimum; a no-violation result remains `untested`. Evidence: [`cadyx/core.py`](../cadyx/core.py), [`cadyx/workspace.py`](../cadyx/workspace.py), [`native/kernel.cpp`](../native/kernel.cpp), [engineering validation contract](../docs/engineering-validation.md). Remaining: a method that can certify a global minimum wall thickness.

15. **Deferred candidate — Human-in-the-loop curve editing:** if requested, consider a constrained editor for traced contours and arcs with local drafts, undo/redo, immutable versioned saves, source-image hash and coordinate-system provenance, and authoritative server-side geometry recomputation/validation before saving. Keep CADYX's browser observation-only by default; this candidate does not authorize general browser modeling controls.

## Sequencing gates

- Plan format migrations alongside any change that evolves persisted project or document data.
- Multiple current host processes may share a workspace on one local machine after stage 5; older hosts, direct writers and network filesystems do not participate in the lease contract.
- Do not expose the host on a LAN until stage 10 is complete.
- Start Scan-to-CAD only when the geometry kernel and Document Model foundations from stages 1 and 3 are adequate for editable reconstruction.
- Implement proposed exports and validation through CADYX's existing native kernel/runtime unless a separate compatibility review justifies another toolchain. External CAD scripting environments and virtual environments may use incompatible Python ABIs or kernel versions; do not treat them as drop-in replacements.
- Keep file export and expensive analysis atomic, revision-bound, observable through progress, and non-destructive to imported sources or existing outputs.
- A validation report may claim only the checks actually performed; dimensional/sampling checks must retain their method and scope, and physical fit/print claims require separate external evidence.

Before marking a stage complete, verify its result against the current code and relevant checks, then update this roadmap. Architecture details and current implementation constraints remain in [the architecture guide](docs/architecture.md); durable technical decisions belong in [decisions](decisions.md).

## Maintainability review — 2026-10-16

The following candidates come from a direct review of the current `main` implementation. They are intentionally scoped as refactors with preserved external behavior; each should land with regression tests before any adjacent feature work depends on it.

16. **Candidate — Command registry and Command System decomposition:** replace the long manual `CommandSystem.execute` dispatch chain with a registry that binds each public command type to its handler and command metadata, then split command families into focused modules while keeping one atomic execution boundary. `cadyx/commands.py` has grown into a high-change hotspot and currently mixes dispatch, validation, sketch authoring, feature construction, scan import, STEP import/export and delivery concerns. Acceptance: command lookup is data-driven, unknown-command behavior is unchanged, command-family modules have isolated tests, and no persisted command/history contract changes. Evidence: [`cadyx/commands.py`](../cadyx/commands.py), [`cadyx/capabilities.py`](../cadyx/capabilities.py), [`tests/test_document.py`](../tests/test_document.py), [`tests/test_profile_features.py`](../tests/test_profile_features.py), and [`tests/test_sketch_creation_tools.py`](../tests/test_sketch_creation_tools.py).

17. **Candidate — Single-source command/API contracts:** eliminate manually duplicated command descriptions and input shapes across discovery metadata, MCP schemas and execution routing. Define one machine-readable contract per public command/API operation and derive capability discovery plus MCP input schemas from it while keeping runtime geometry/reference validation authoritative in Core/Command System. Add parity tests that fail when a supported command is missing from discovery/MCP or when required/optional fields drift. Evidence: [`cadyx/capabilities.py`](../cadyx/capabilities.py), [`cadyx/mcp_server.py`](../cadyx/mcp_server.py), [`cadyx/commands.py`](../cadyx/commands.py), and [`tests/test_mcp_server.py`](../tests/test_mcp_server.py).

18. **Candidate — Centralized project availability and lifecycle policy:** factor the repeated `FREE`/recovery/running-operation checks in `CadyxCore` into explicit policy helpers for read, write, file-management, selection and destructive operations. Preserve fail-closed behavior and existing error codes while making it impossible for a new endpoint to accidentally omit one part of the availability invariant. Add table-driven tests for FREE, active lease, recovery-required and running-activity states. Evidence: [`cadyx/core.py`](../cadyx/core.py), [`cadyx/lease.py`](../cadyx/lease.py), [`cadyx/events.py`](../cadyx/events.py), [`tests/test_locking.py`](../tests/test_locking.py), and [`tests/test_multiprocess_leases.py`](../tests/test_multiprocess_leases.py).

19. **Candidate — Declarative HTTP routing and transport decomposition:** split the large stdlib request-handler branches into a small route table plus focused transport helpers for workspace, project, agent, validation, viewport, file and scanner endpoints. Keep `CadyxCore` authoritative and preserve authentication, payload limits, SSE behavior and exact status/error contracts. Acceptance: route matching is testable without opening a socket, GET/POST path parsing no longer depends on long ordered `if` chains, and the existing Web API suite remains behaviorally identical. Evidence: [`cadyx/web.py`](../cadyx/web.py), [`tests/test_web_api.py`](../tests/test_web_api.py), and [`tests/test_auth.py`](../tests/test_auth.py).

**Recommended order:** 17 → 16 → 18 → 19. Unifying the contract first reduces drift while the Command System is split; lifecycle policy can then be reused by the decomposed HTTP routes.
