# CADYX project roadmap

This is the current development sequence. The milestones are goals, not claims that the corresponding capabilities are entirely absent; inspect the implementation before starting work or changing a milestone's status. Stages 1–7 are complete; later stages remain proposed.

## Stages

1. **Complete — Real geometry kernel:** integrate Open CASCADE behind `GeometryKernel`, validate reconstructed box B-reps, retain compatibility with saved `primitive-v1` descriptors, and cover the adapter with conformance tests. Evidence: [`cadyx/kernel.py`](../cadyx/kernel.py), [`tests/test_kernel.py`](../tests/test_kernel.py), and [runtime setup](../scripts/setup-runtime.ps1).
2. **Complete — Live visual workspace:** show supported box geometry and parameter changes in the browser as the Agent API updates the project; keep SSE command details out of the UI. Current scope supports box previews. Evidence: [`web/`](../web/), [`cadyx/web.py`](../cadyx/web.py), and [architecture](../docs/architecture.md).
3. **Complete — Richer Document Model:** persisted XY sketches with points, lines, circles, checked horizontal/vertical/coincident/distance/radius constraints, stable typed UUID references, atomic batch edits and guarded deletion. Constraints validate supplied geometry; no solver or browser sketch editor is included. Document v1 upgrades explicitly to v2 in memory, preserving legacy solids/history. Evidence: [`cadyx/models.py`](../cadyx/models.py), [`cadyx/sketches.py`](../cadyx/sketches.py), [`cadyx/commands.py`](../cadyx/commands.py), [`tests/test_document.py`](../tests/test_document.py), [`tests/test_web_api.py`](../tests/test_web_api.py), and [document contract](../docs/document-model-v2.md).
4. **Complete — Project Format migrations:** explicit sequential migrations with independent project-envelope/document versions, copy-only reads, current-schema validation and persistence through successful leased commands and the existing atomic save path. Envelope v1 and document v2 remain current. Evidence: [`cadyx/migrations.py`](../cadyx/migrations.py), [`tests/test_migrations.py`](../tests/test_migrations.py), [`tests/test_web_api.py`](../tests/test_web_api.py), and [migration contract](../docs/project-format-v1.md#migration-contract).
5. **Complete — Multi-process leases:** durable per-project SQLite leases and a shared lock spanning the full Core command, inspection and validated stale-lease recovery on local filesystems; process crashes retain recoverable lease ownership and atomic project state. Independent projects remain concurrent. SSE stays process-local. Evidence: [`cadyx/lease.py`](../cadyx/lease.py), [`cadyx/core.py`](../cadyx/core.py), [`tests/test_multiprocess_leases.py`](../tests/test_multiprocess_leases.py), and [lease contract](../docs/architecture.md#edit-leases).
6. **Complete — Safe agent stop and resume:** durable per-token stop fences reject queued commands while an admitted atomic command finishes; saved document and geometry validate before the agent lease is freed. Resume validates the expected revision and issues a fresh lease whose commands require revision checks. Saved history resolves uncertain command outcomes without automatic replay. Existing lease acquisition remains compatible; no embedded runtime or UI stop controls are included. Evidence: [`cadyx/core.py`](../cadyx/core.py), [`cadyx/lease.py`](../cadyx/lease.py), [`cadyx/web.py`](../cadyx/web.py), [`tests/test_agent_control.py`](../tests/test_agent_control.py), [`tests/test_multiprocess_leases.py`](../tests/test_multiprocess_leases.py), [`tests/test_web_api.py`](../tests/test_web_api.py), and [stop/resume contract](../docs/architecture.md#safe-agent-stop-and-resume).
7. **Complete — Shared rendering and viewport API:** identical read-only scene endpoints for browser/agents, native OCCT tessellation of supported bodies, XY sketch points/lines/circles, stable object ids and scene bounds/revision. A shared Z-up orthographic canvas viewport renders CAD scenes and PLY with orbit, zoom, fit and client camera API; document refresh retains the camera. The latest stable Python/OCCT runtime uses a native C ABI bridge. No editor, picking or new solid operations are included. Evidence: [`cadyx/rendering.py`](../cadyx/rendering.py), [`native/`](../native/), [`web/viewport.js`](../web/viewport.js), [`tests/test_rendering.py`](../tests/test_rendering.py), [`tests/test_viewport.cjs`](../tests/test_viewport.cjs), and [viewport contract](../docs/viewport-api.md).
8. **Model inspection and manual editing:** expand browser inspection and guarded manual edits under a human lease beyond the current box preview and manual test form.
9. **Provider-neutral Agent Runtime:** add an agent runtime without coupling Core to a specific AI provider.
10. **Authentication before LAN access:** implement and verify authentication before supporting access from other machines.
11. **Scan-to-CAD:** build scan preprocessing and editable reconstruction after the geometry foundation is established.

## Sequencing gates

- Plan format migrations alongside any change that evolves persisted project or document data.
- Multiple current host processes may share a workspace on one local machine after stage 5; older hosts, direct writers and network filesystems do not participate in the lease contract.
- Do not expose the host on a LAN until stage 9 is complete.
- Start Scan-to-CAD only when the geometry kernel and Document Model foundations from stages 1 and 3 are adequate for editable reconstruction.

Before marking a stage complete, verify its result against the current code and relevant checks, then update this roadmap. Architecture details and current implementation constraints remain in [the architecture guide](../docs/architecture.md); durable technical decisions belong in [decisions](decisions.md).
