# CADYX project roadmap

This is the current development sequence. The milestones are goals, not claims that the corresponding capabilities are entirely absent; inspect the implementation before starting work or changing a milestone's status. Stages 1–12 are complete.

## Stages

1. **Complete — Real geometry kernel:** integrate Open CASCADE behind `GeometryKernel`, validate reconstructed box B-reps, retain compatibility with saved `primitive-v1` descriptors, and cover the adapter with conformance tests. Evidence: [`cadyx/kernel.py`](../cadyx/kernel.py), [`tests/test_kernel.py`](../tests/test_kernel.py), and [runtime setup](../scripts/setup-runtime.ps1).
2. **Complete — Live visual workspace:** show supported CAD bodies, sketch geometry and parameter changes in the browser as APIs update the project; animate meaningful sketch edits and extrusion, revolution, sweep, Boolean fuse and fillet operations. Activity snapshots and SSE carry detailed operation status and progress, while the browser shows one compact action/result status; the selected project stays visible during agent work. Evidence: [`web/`](../web/), [`cadyx/web.py`](../cadyx/web.py), and [architecture](docs/architecture.md).
3. **Complete — Editable Document Model and feature history:** persisted XY/XZ sketches with points, lines, circles, checked horizontal/vertical/coincident/distance/radius constraints, stable typed UUID references, atomic batch edits and guarded deletion. Closed profiles create editable OCCT extrusion/revolution features; open sketch paths create B-spline circular-pipe sweeps; source bodies can be fused into one solid and topology-selected edges filleted. Replacing or editing sketch profiles/paths and changing supported feature parameters rebuilds dependent features atomically. Constraints validate supplied geometry; no solver or browser sketch editor is included. Document v1/v2 upgrade explicitly to v3 in memory, preserving legacy solids/history. Evidence: [`cadyx/models.py`](../cadyx/models.py), [`cadyx/sketches.py`](../cadyx/sketches.py), [`cadyx/commands.py`](../cadyx/commands.py), [`tests/test_profile_features.py`](../tests/test_profile_features.py), and [document contract](docs/document-model-v3.md).
4. **Complete — Project Format migrations:** explicit sequential migrations with independent project-envelope/document versions, copy-only reads, current-schema validation and persistence through successful leased commands and the existing atomic save path. Envelope v1 and document v3 are current. Evidence: [`cadyx/migrations.py`](../cadyx/migrations.py), [`tests/test_migrations.py`](../tests/test_migrations.py), [`tests/test_web_api.py`](../tests/test_web_api.py), and [migration contract](docs/project-format-v1.md#migration-contract).
5. **Complete — Multi-process leases:** durable per-project SQLite leases and a shared lock spanning the full Core command, inspection and validated stale-lease recovery on local filesystems; process crashes retain recoverable lease ownership and atomic project state. Independent projects remain concurrent. SSE stays process-local. Evidence: [`cadyx/lease.py`](../cadyx/lease.py), [`cadyx/core.py`](../cadyx/core.py), [`tests/test_multiprocess_leases.py`](../tests/test_multiprocess_leases.py), and [lease contract](docs/architecture.md#edit-leases).
6. **Complete — Safe agent stop and resume:** durable per-token stop fences reject queued commands while an admitted atomic command finishes; saved document and geometry validate before the agent lease is freed. Resume validates the expected revision and issues a fresh lease whose commands require revision checks. Saved history resolves uncertain command outcomes without automatic replay. Existing lease acquisition remains compatible; no embedded runtime or UI stop controls are included. Evidence: [`cadyx/core.py`](../cadyx/core.py), [`cadyx/lease.py`](../cadyx/lease.py), [`cadyx/web.py`](../cadyx/web.py), [`tests/test_agent_control.py`](../tests/test_agent_control.py), [`tests/test_multiprocess_leases.py`](../tests/test_multiprocess_leases.py), [`tests/test_web_api.py`](../tests/test_web_api.py), and [stop/resume contract](docs/architecture.md#safe-agent-stop-and-resume).
7. **Complete — Shared rendering and viewport API:** identical read-only scene endpoints for browser/agents, native OCCT tessellation of boxes, extrusion/revolution profiles, swept pipes, fused solids and filleted solids, plus direct rendering of editable scan triangle meshes and XY/XZ sketch points/lines/circles. Scenes expose stable object ids and bounds/revision. A shared Z-up orthographic canvas viewport renders CAD scenes and PLY with orbit, zoom, fit and client camera API; Agent API camera events animate a visible browser orbit without synthesizing input, and document refresh retains the camera. Scan meshes remain distinct from B-reps and are not Boolean/fillet inputs. The latest stable Python/OCCT runtime uses a native C ABI bridge. No viewport picking or browser sketch editor is included. Evidence: [`cadyx/rendering.py`](../cadyx/rendering.py), [`native/`](../native/), [`web/viewport.js`](../web/viewport.js), [`tests/test_rendering.py`](../tests/test_rendering.py), [`tests/test_profile_features.py`](../tests/test_profile_features.py), [`tests/test_viewport.cjs`](../tests/test_viewport.cjs), [`tests/test_web_api.py`](../tests/test_web_api.py), and [viewport contract](docs/viewport-api.md).
8. **Complete — CAD model inspection and API-first authoring:** use a read-only, full-window detail view with collapsed model and property docks. Agents create projects and author/edit bodies, sketches, geometry, constraints and dependent solid features through the existing Agent API and Core command system; they can inspect current B-rep edge topology for fillets and retrieve server-rendered PNG snapshots directly through `viewport.png`. SSE updates the observation view after committed changes and animates API-requested camera orbits and modeling operations, without a manual page refresh. The browser provides observation only. Evidence: [`web/index.html`](../web/index.html), [`web/app.js`](../web/app.js), [`web/style.css`](../web/style.css), [`cadyx/rendering.py`](../cadyx/rendering.py), [`tests/test_web_api.py`](../tests/test_web_api.py), [`tests/test_profile_features.py`](../tests/test_profile_features.py), [Agent API contract](docs/document-model-v3.md#browser-inspection-and-agent-api-editing), and [viewport contract](docs/viewport-api.md).
9. **Complete — Provider-neutral Agent Runtime:** add an in-process runtime with a provider adapter protocol, bounded tool loop, project inspection and viewport tools, and revision-protected Command System execution under managed agent leases. Core remains provider-independent and no provider SDK or adapter is bundled. Evidence: [`cadyx/agent_runtime.py`](../cadyx/agent_runtime.py), [`tests/test_agent_runtime.py`](../tests/test_agent_runtime.py), and [runtime contract](docs/architecture.md#agent-runtime).
10. **Complete — Authentication before LAN access:** reject unauthenticated non-loopback binds; protect the browser, API, workspace files, viewport and SSE with a configured token; keep only minimal health status public. Tokens come from one validated runtime source, and the default persistent host remains loopback-only. Evidence: [`cadyx/auth.py`](../cadyx/auth.py), [`cadyx/__main__.py`](../cadyx/__main__.py), [`cadyx/web.py`](../cadyx/web.py), [`tests/test_auth.py`](../tests/test_auth.py), and [authentication contract](docs/architecture.md#http-authentication-and-lan-bind-gate).
11. **Complete — Scan-to-CAD:** import direct workspace PLY triangle meshes and point clouds, clean/simplify meshes or reconstruct point-cloud surfaces with CPU Open3D, and persist editable `cadyx-mesh-v1` geometry plus bounded parameters/source hash in the document. Export each processed mesh as an atomic content-addressed PLY beside its unchanged source. Publish actual operation phases and recent activity in Core snapshots and Agent API/SSE data; show one compact action/result status in the browser. Evidence: [`cadyx/scan.py`](../cadyx/scan.py), [`native/scan.cpp`](../native/scan.cpp), [`cadyx/mesh_geometry.py`](../cadyx/mesh_geometry.py), [`cadyx/commands.py`](../cadyx/commands.py), [`web/`](../web/), [`tests/test_scan.py`](../tests/test_scan.py), [`tests/test_web_api.py`](../tests/test_web_api.py), [scan command contract](docs/document-model-v3.md#scan-import-and-editable-triangle-meshes), and [runtime setup](../scripts/setup-runtime.ps1). Checks: native runtime setup/build, real mesh and point-cloud sample processing in an isolated temporary workspace, scan/API/Agent Runtime and kernel/document/rendering test modules.
12. **Complete — Engineering gears and threads:** build unshifted external involute spur-gear outlines through the existing XY sketch command, and single-start external ISO metric thread solids as editable native OCCT features. Preserve Document Model v3 and agent-only modeling; animate profile strokes and thread creation in the live viewer. Evidence: [`cadyx/engineering.py`](../cadyx/engineering.py), [`cadyx/commands.py`](../cadyx/commands.py), [`native/kernel.cpp`](../native/kernel.cpp), [engineering profile contract](docs/document-model-v3.md#engineering-profiles), [`tests/test_engineering_features.py`](../tests/test_engineering_features.py), and [viewport contract](docs/viewport-api.md). Checks: native OCCT rebuild, targeted engineering feature tests, and live Agent API demo projects for a 20/40-tooth module-2 gear pair and a parameter-edited M12x1.5 thread.

## Sequencing gates

- Plan format migrations alongside any change that evolves persisted project or document data.
- Multiple current host processes may share a workspace on one local machine after stage 5; older hosts, direct writers and network filesystems do not participate in the lease contract.
- Do not expose the host on a LAN until stage 10 is complete.
- Start Scan-to-CAD only when the geometry kernel and Document Model foundations from stages 1 and 3 are adequate for editable reconstruction.

Before marking a stage complete, verify its result against the current code and relevant checks, then update this roadmap. Architecture details and current implementation constraints remain in [the architecture guide](docs/architecture.md); durable technical decisions belong in [decisions](decisions.md).
