# CADYX project roadmap

This document preserves milestone and source-audit history. Historical feature limitations describe the original stage, not necessarily the current implementation. Foundation stages 1–14 are complete in their documented scope; stage 15 remains deferred. The operational sequence below takes precedence over historical priority labels; confirm current code before treating an older candidate as outstanding.

## Current execution roadmap — 2026-10-29

**Baseline:** `main` reviewed at commit `c4a6e35` (2026-10-29). The authoritative schema is project envelope **v1**, document **v16**, assembly graph **v7**; check `cadyx/migrations.py`, `docs/README.md` and current tests rather than treating the v7/v9 introduction documents as present-day limits. Agent-initiated modeling continues through the revision-checked Agent API/MCP and Core lease/Command System. The current task authorizes human assembly editing through the same Core and lease boundary; arbitrary browser-based agent control and code execution are not authorized.

**Implemented in source, not automatically runtime-verified:** P0 agent accuracy work (typed topology queries, deterministic sketch solver, transactional previews, diagnostics, compact inspection, `check_project`, deterministic rebuild); Document v9–v12 assemblies/part instances, mates, material properties, discrete-pose interference checks, catalog presets, geometry-aware revision comparisons and XY/XZ/YZ/custom/face work planes; single-call agent command execution and compact receipts; persistent MCP HTTP connections and bounded downstream response reads; SSE replay; direct project point-cloud persistence and scanner/live viewport improvements. A committed implementation or added test is **not** proof that Windows OCCT/Open3D native and browser CI passed. Do not claim continuous collision clearance, true physical PLY scale, general arbitrary-plane loft/revolve, certified vendor parts, automatically computed manufacturing suitability, or a complete technical drawing pipeline.

Run the configured native-free source and Windows x64 OCCT/Open3D/browser CI against **the actual current head**, including migrations v1→v16, assembly v7, source-to-instance rendering, sketch plane attachment and rebuild, scan import/point-only vs triangle-mesh behavior, Agent API/MCP error paths, revision comparison and authenticated SSE reconnect. Check pass/fail/untested semantics, original input preservation, provenance and final lease `FREE`. Prefer independently measured known-dimension fixtures for scanner scale.
3. Fix confirmed root causes and add regression tests before reclassifying any source-only milestone as runtime-verified. Recheck `scripts/runtime-versions.json` against official stable dependencies when changing a runtime; do not downgrade or bypass integrity checks to mask failures.

### Next — safety and recovery under load (P0)

- Close the evidence-backed connection/request/cancellation gaps in audit **49, 50, 51, 54, 69, 70, 85, 95 and 104**, in dependencies-first order: malformed/truncated body rejection and bounded deadlines, immutable event payloads, bounded provider/MCP work queues and input frames, explicit request cancellation, and unambiguous mutation recovery without automatic replay. For item 85, require durable idempotency/receipt provenance or an equally strong recovery contract before enabling retries.
- Acceptance: malformed or oversized input and stalled clients cannot pin command admission indefinitely; concurrent observers cannot starve an edit; cancellation never misreports a potentially committed write; after an uncertain response the caller can determine the saved revision/result before issuing another command. Preserve atomic saves, stop fences, lease ownership and existing error envelopes.

### Then — measured agent ↔ CADYX throughput (P1)

- **Do not reopen completed work:** audit **79** (single `/commands/execute` request with managed short lease), **80** (thread-local pooled keep-alive HTTP) and **93** (compact server-side command receipt) are already implemented in source as of 2026-10-19. Existing compact inspection partly addresses **83**; a cheaper dedicated preflight must be justified with measurements rather than recreated blindly. Audits **113/114/117** likewise describe source improvements; confirm benchmarks/CI before judging final impact.
- Instrument **106** first (opt-in end-to-end p50/p95, bytes, tool round-trips, Core/native/serialization time, conflicts) without sensitive payload logging. Then compare the remaining candidates **81, 84, 86–90, 99–103 and 105** against representative 1-command, 20-command, assembly, large-scene and scanner workloads. Prioritize actual agent latency or output-size bottlenecks, not raw checklist order.
- Acceptance: measurable before/after latency and memory/byte budgets, stable revision-checked outputs, no stale topology/viewport cache after mutation, no loss of meaningful viewer animations, and no increase in ambiguous write outcomes.

### Product follow-through — engineering deliverables and scanning (P1 / scoped P2)

- Stabilize the implemented assembly/kinematics/material/validation v9–v12 stack before promoting **P1-15 technical drawings, sections and BOM**. First deliver an explicitly requested, revision-bound, unit-checked drawing/BOM subset with provenance, conservative `untested` fields and atomic non-overwriting outputs; native assembly STEP export and vendor certification are separate scope decisions.
- Stabilize the end-to-end Revopoint-to-CAD path: capture and preview, user-approved frame/table calibration, explicit unit/scale reference, point-only source retention, deterministic triangle-mesh reconstruction where required, scan sections, editable OCCT modeling and sampled comparison. Direct point-cloud import **does not** authorize triangle-based section/fit operations. Multi-scan ICP from P2-16 remains a separately benchmarked candidate, not a completed production registration guarantee.
- Keep P2 CAE, manufacturability, sheet metal, GD&T, mechanism simulation and the optional human curve editor demand-led; do not silently elevate them above recovery, verification or reproducible core geometry.

**Decision rule:** Promote a milestone to *verified complete* only with an implementation reference, a checked current-revision test/CI result and a bounded end-to-end scenario. Otherwise use *implemented in source; verification pending*, *partial*, *candidate* or *deferred*. No calendar delivery dates are committed here.

### Non-negotiable product and control boundary

- **CADYX is a tool, not an autonomous AI application.** A separately operated external AI agent (for example Codex, Claude Code or another MCP/HTTP client) owns user intent, planning, choosing actions, interpretation, retry decisions, goal completion, and any training/optimization loops. CADYX itself neither originates goals nor independently plans, chooses a design, calls an LLM, schedules self-directed CAD work, autonomously retries/refines a model, or ships an embedded chat assistant. The existing optional, provider-neutral in-process Agent Runtime is a *client-invoked orchestration adapter*, not a background autonomous operator; do not add a bundled model/provider or a self-starting task loop.
- New intelligence-like functions must be **deterministic, bounded, caller-invoked geometric algorithms**, validators, solvers, or declarative command compositions. Existing self-evolving capabilities remain explicitly proposed and tested compositions of known commands without generated-code execution; they do not authorize self-initiated capability development or arbitrary Python/shell execution.
- **One authoritative mutation path:** versioned Agent API/MCP → Core/Command System → lease/revision check → validated, atomic saved state. Read-only inspection may run without holding an edit lease; the external agent must never hold a lease while thinking or waiting on a provider. New long computations must accept explicit caller parameters, cancellation/budgets and report progress. Failed, stale, ambiguous and unsupported operations must fail explicitly, not silently pick another geometry.
- **Browser = passive human observation.** Preserve desktop-only read-only geometry/progress/activity. Any future human-edit mode is separately authorized and available only after the agent's edit lease and active-operation state are both confirmed free; never enable simultaneous human/agent edits. No mouse/DOM automation as an agent control path, no modeling toolbar/chat as a prerequisite for a capability.
- Validation must distinguish **pass / fail / untested**, name its measurement method, units, bounds, tolerances and revision, and never claim manufacturing safety, fit, stress or printability from a limited screen. Keep original CAD/scan inputs, provenance and valid preceding revisions. Treat tool/format/library code from third parties as untrusted; review licensing, versioning, integrity and sandbox boundaries rather than executing arbitrary part scripts.
- Expand shared command schemas/capability discovery rather than proliferating narrowly overlapping MCP tools; return compact machine-readable, revision-tagged results and structured diagnostic evidence. Preserve visible CAD operations, event ordering and contract compatibility. Add migrations and source/native/browser tests only where the new feature requires them.

### Cross-cutting optimizations and implementation gates

The **existing performance/maintainability backlog (items 16–117 below)** remains the detailed, evidence-bearing source for already completed work and outstanding hot paths; do not re-open completed candidates or renumber those source audits just because this section is added. In particular, retain their measured-first priorities for kernel batch Booleans, sketch/document indices, tessellation caching, scan BVH/contour complexity, SSE admission/replay, bounded MCP response buffering, compact tool payloads, snapshot encoding and lifecycle cleanup.

- **O1 — Reduce agent round-trips, not just server compute.** Use versioned capability discovery, grouped *read-only* inspections and the explicit transaction-preview path (items 1, 3, 6), and compact structured receipts. Measure end-to-end external-agent tool calls, transmitted bytes/tokens and p50/p95 time per successful feature rather than declaring a faster kernel sufficient. Preserve one observable event per committed, meaningful modeling action; do not automatically batch away animations or hide important intermediate results.
- **O2 — Incremental dependency-aware recomputation.** Build on existing v8 parameter/rebuild paths to avoid recomputing unaffected geometry, topology inspections, tessellations, validation stages and assembly instances; use revision/geometry hash and relevant parameters as cache keys. Bound cache memory, invalidate on all dependent edits, and compare cold/warm correctness plus peak memory before enabling caching.
- **O3 — Bound expensive work and isolate failures.** Introduce per-operation time, memory, feature/triangle count and output-size budgets where appropriate, explicit cancellation and typed resource-limit failures. For optional catalog/solver/simulation backends, use least-privilege, isolated workers and provenance-checked inputs; never promote untrusted part scripts to the core command execution path. Preserve last good committed geometry and imported sources.
- **O4 — Keep observation cheap and nonblocking.** Reuse the existing viewport/thumbnail/Ply/event performance items (especially 63, 109–115). Benchmark desktop frame time, server responsiveness to agent commands under multiple passive viewers, snapshot freshness and SSE catch-up; a read-only browser must not throttle or block agent control.
- **O5 — Contract, type and migration quality.** Share typed input/output/operation metadata across HTTP, MCP and Core; add regression/property/fuzz testing around topology ambiguity, constraint solver degeneracy, assemblies, invalid imports, migration and atomic rollback. Keep native Windows CI authoritative for OCCT, with a cheaper native-free source gate. Avoid broad new frameworks unless a validated performance/correctness improvement justifies them.
- **O6 — Geometry-aware progress, not autonomous activity.** Return phase, elapsed/cost and checkpoint/receipt metadata only for operations explicitly invoked by an external agent. No internal plan generator, unattended task queue, automatically triggered regeneration after arbitrary filesystem change, background optimization, autonomous repair or self-directed CAD design. Continue to honor `FREE` / revision / lease / stop-fence boundaries on every mutation.

**Suggested dependency order:** P0 geometry query → sketch solver → transaction preview/diagnostics → compact inspection and headless project CI → deterministic checks. Then P1 work planes and assembly instance schema → mates → interferences/mass → catalog and geometry diff → drawings/BOM. P2 scan registration/manufacturability/FEM/sheet metal/GD&T/simulation/benchmarking only when concrete externally requested modeling or validation tasks justify their cost. Parallelize independent *read-only* work when safe, but serialize writes per project under the existing Core lease. No new branches: do normal implementation work on `main` per repository rules; do not treat this roadmap update as permission to implement the candidates immediately.

## Sequencing gates

- Plan format migrations alongside any change that evolves persisted project or document data.
- Multiple current host processes may share a workspace on one local machine after stage 5; older hosts, direct writers and network filesystems do not participate in the lease contract.
- Do not expose the host on a LAN until stage 10 is complete.
- Start Scan-to-CAD only when the geometry kernel and Document Model foundations from stages 1 and 3 are adequate for editable reconstruction.
- Implement proposed exports and validation through CADYX's existing native kernel/runtime unless a separate compatibility review justifies another toolchain. External CAD scripting environments and virtual environments may use incompatible Python ABIs or kernel versions; do not treat them as drop-in replacements.
- Keep file export and expensive analysis atomic, revision-bound, observable through progress, and non-destructive to imported sources or existing outputs.
- A validation report may claim only the checks actually performed; dimensional/sampling checks must retain their method and scope, and physical fit/print claims require separate external evidence.

Before marking a stage complete, verify its result against the current code and relevant checks, then update this roadmap. Architecture details and current implementation constraints remain in [the architecture guide](docs/architecture.md); durable technical decisions belong in [decisions](decisions.md).

HTTP error overrun retains the status and preserves existing deterministic-rejection vs. ambiguous-mutation behavior; oversized command success must be fenced and not replayed. **Acceptance coverage added:** exact-limit and over-limit bodies, missing/declared length, per-type budgets, HTTP error status preservation, safe-stop and non-replay after a committed command. **Expected metric:** bounded HTTP wire bytes per request, including up to one extra over-limit byte, measured before JSON/base64 amplification; compare peak bridge RSS and reject time for large responses in CI. **Risks:** Valid very large data now requires paged/filtered APIs or direct staged import; the cap does not limit post-read object allocations. Canonical contract: [MCP bridge](docs/architecture.md#agent-api-discovery-and-local-codex-mcp-adapter).

115. **Reduce browser PNG snapshot capture work during continuous animations** — **P1**, **impact/effort:** Medium / Medium. **Evidence:** `web/browser-state.js:40–122`; `cadyx/core_services.py:915–964`. **Problem:** The snapshot synchronizer runs `capture()` after each dirty interval (default 400 ms), then uploads a full PNG even when further dirty frames supersede it. Long camera or geometry animations can consume browser encoding time and compete with live rendering. **Proposed fix / status:** Coalesce to latest revision/camera state, avoid redundant captures of unchanged final frames, and adapt scheduling while keeping timely inspectable frames and all visible animations. Do not drop real command events. **Expected effect / metric:** Measure PNG encodes/uploads per 30-second animated model operation, main-thread frame time (p95), bytes uploaded and freshness of the published snapshot. **Risks:** Aggressive throttling would make AI visual inspection stale; guard project/revision identity and preserve bounded freshness.

116. **Retire per-project lifecycle locks after project deletion** — **P2**, **impact/effort:** Low / Low-Medium. **Evidence:** `cadyx/core_services.py:68–74,179–185,274–292`. **Problem:** `_project_lifecycle_locks` stores an `RLock` for every project ID touched and never removes entries when projects are deleted. In long-running hosts with repeated project churn this dictionary grows for the process lifetime. **Proposed fix / status:** Use lifecycle-safe weak-valued locks or reference-counted retirement only after no holders/waiters remain; test simultaneous operations and deletion. **Expected effect / metric:** Measure resident lock entries and retained bytes after thousands of create/inspect/delete cycles; target retained entries proportional to live/active projects. **Risks:** Removing a lock with waiting threads could admit two independent locks for one ID; require adversarial concurrency tests.

117. **Use compact JSON for high-frequency HTTP and SSE transport payloads** — **P2**, **impact/effort:** Low-Medium / Low. **Evidence:** `cadyx/web.py:245–260,400–404`. **Problem:** Default `json.dumps` separators insert spaces in all API JSON responses and SSE envelopes. This sends avoidable bytes on every operation/status poll and event, especially when data contains many fields. **Proposed fix / status:** Pass `separators=(',', ':')` for HTTP JSON and SSE event serialization while preserving Unicode, finiteness checks, headers and parsed structure. **Implemented in this commit**. **Expected effect / metric:** Track JSON body byte count and serialization time for typical `/updates`, command and event fixtures; expect smaller payloads but do not claim measured p95 savings. **Risks:** Clients must parse JSON, not compare literal whitespace; preserve SSE framing and Content-Length correctness.

No further runtime refactors in this commit; verify using representative measurements and regression suites before marking any other candidate complete.
